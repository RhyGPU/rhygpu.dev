004, Feeding the Model a Session Packet

Context Compiler V2, clean recent chat, and state injection

May 2026 · Context Compiler V2 · Provider payloads and state injection

Context Compiler V2 is where the input side started becoming real.

The app already had the output path taking shape. The model could return narration with a hidden-state block, the app could strip the block, decode it, and start updating Soul and World behind the curtain.

Now the next turn needed the reverse path.

The model had to get the session back.

Not as raw chat history forever. That was the exact kind of bloat I was trying to avoid. But also not as one dead summary that cuts out the rhythm of the scene.

I needed a packet.

Current state, character memory, recent events, relationship pressure, world information, and a few recent clean messages.

The whole session, but carried forward as state.

What changed

Context Compiler V2 started building the next provider payload from actual session pieces instead of treating the prompt as a loose pile.

The packet centered on:

  • CURRENT STATE
  • CHARACTER MEMORY
  • RECENT EVENTS
  • RELATIONSHIP
  • WORLD
  • clean recent messages

That last part matters.

The recent messages stay clean. No hidden block. No machine JSON. No encoded state being fed back into the model raw.

The hidden state is for the engine. The visible narration is for the chat history. The compiled packet is what the model gets next.

That separation is the whole point.

Why I touched this

The external API tests made the problem obvious fast.

Without the right input shape, the model drifts back into normal RP chatbot behavior. It talks as the character. It forgets that it is supposed to be a narrator. It treats prompt instructions like vibes instead of rules. It can also start mixing character knowledge, narrator knowledge, and user action if the payload is sloppy.

That was worrying because Mnemosyne is not supposed to be another character impersonator.

The app has to hold the session together.

The model writes from the state, but the model should not be trusted to carry the whole state by itself.

That was the real pressure behind this work.

How the packet works

The turn loop now starts to look like this:

Soul
World Log
Recent Events
Relationship State
Clean Recent Messages
        ↓
Context Compiler V2
        ↓
Provider Payload
        ↓
Model Response
        ↓
Visible Narration + Hidden State
        ↓
Strip / Parse
        ↓
Soul / World Patch
        ↓
Updated Session State
        ↓
Compile again

That is the engine shape I wanted.

The model still does the writing. The app carries the session.

The clean recent messages keep the prose alive. They preserve the last exchange, the tone, and the immediate rhythm.

The compiled state carries the long-term part: what the character remembers, where the scene is, what recently happened, and what the current relationship pressure looks like.

One side keeps the writing from going cold.

The other side keeps the session from going empty.

What got better

The model is no longer starting from only a few recent chat turns.

It gets a compact version of the session before writing: current scene, character memory, world state, recent events, relationship pressure, and the last clean messages.

That makes the whole thing easier to reason about.

If the next response goes wrong, I can check the payload.

Maybe the model ignored the instructions. Maybe the compiled packet missed something important. Maybe the recent chat window was too short. Maybe the world state was stale.

That is still annoying, but it is better than the old version of the problem where the answer was just “the AI forgot.”

Now there is a place to look.

Why the categories matter

The Soul and World Log split only works if the compiler preserves it.

A character memory is not the same kind of thing as a room fact.

Relationship pressure is not the same thing as active plot.

Recent dialogue is not the same thing as long-term identity.

If those get mashed together, the model will mash them together too. That is how a character starts knowing narrator-only information, or how old emotional tension keeps bleeding into every scene.

So the packet needs sections.

Soul stays Soul-shaped.

World stays World-shaped.

Relationship stays relationship-shaped.

Recent messages stay as actual chat texture.

That sounds simple, but this is where the design starts paying rent. The split from earlier finally becomes something the app can feed into a model call.

Patch protocol entering the same range

Patch protocol started showing up here because compiled state creates a new problem.

If the app sends state forward every turn, then state changes need to be traceable.

A memory should not just appear.

A world event should not just mutate.

A relationship shift should not become permanent without knowing which turn caused it.

Regenerate, correction, restore, and branch logic all need that trail later.

So the input side and the patch foundation belong near each other. One decides what the next model call sees. The other starts making state changes explicit enough to survive edits.
