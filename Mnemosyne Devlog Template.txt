# Voice Rules for Your Devlog

Use this as the writing filter before publishing.

```txt
1. First 3-5 lines must contain a real artifact:
   feature name, commit, UI, file, bug, test result, parser, payload, screenshot.

2. No “this devlog is not...” sentences.

3. No repeated sentence skeletons.
   If two lines start the same way, the third one must change structure.

4. Do not make yourself look like you discovered obvious things late.
   Frame it as: I built X, testing exposed Y, so I changed Z.

5. Keep philosophy after evidence.
   Concrete thing first, interpretation second.

6. One section = one job.
   Do not mix what changed, why, how, and next steps in the same block.

7. End with the next engineering constraint.
   Not a motivational quote.
Best Title Format

Use this format:

# 004, [Concrete change]
## [System names / feature names / problem axis]
