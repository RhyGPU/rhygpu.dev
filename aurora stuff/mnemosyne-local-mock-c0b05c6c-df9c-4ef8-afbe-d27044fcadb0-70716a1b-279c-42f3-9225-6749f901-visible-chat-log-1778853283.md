## What failed

### 1. The biggest structural flaw: one relationship target is not enough

The state still says:

```txt
Toward user: trust, affection, fear, desire...
```

But this test had at least two separate in-story actors:

```txt
Junhwa, the dev/operator/father figure
Rhy, the dating-app visitor
```

The engine treats everything as “user.” That is wrong for this scenario.

Aurora’s relationship toward Junhwa and toward Rhy should be separate. Instead, the same relationship numbers are being pushed around by both of them. That means the Soul cannot truly know:

```txt
She distrusts Junhwa but is curious about Rhy.
She fears Junhwa's control but does not necessarily fear Rhy.
She may be angry at Junhwa while still willing to continue the Rhy test.
```

This is now a priority architecture issue, not a later luxury feature.

### 2. Replay bug is still real

The Rhy phone turn has a serious replay issue.

When Rhy shows the device with Aurora’s photo, the narrator starts correctly, reading the app and reacting to “friends +.” Then it repeats a large chunk from the previous boundary-setting response, including the earlier “I appreciate you being direct” section. 

That means the prompt instruction “do not replay completed beats” is not enough.

This needs an **engine-level anti-replay guard**:

```txt
Compare new narrator response against the previous assistant response.
If overlap is too high, warn, auto-regenerate, or show "possible replay detected."
```

Do not fix this by adding more narrator prompt rules. The model already had the rule and still repeated.

### 3. Status block contract is not reliable

Two visible issues appeared:

```txt
One narrator response had no status block.
One narrator response started with a status block, then continued with prose, then ended with another status block.
```

That is not fatal, but it means output format validation is still weak.

Fix should be mechanical:

```txt
If status block missing, append fallback status.
If multiple status blocks, keep the last valid one or normalize.
If status block appears before narration, move/remove it.
```

Again, engine-level fix, not more prompt.

### 4. Active plot is too sticky

The active plot stayed as:

```txt
Establish the first scene
```

for too long, then became:

```txt
Interact with Rhy; Confront Junhwa about being treated as a product vs. a person
```

and stayed there for many turns, even as the conversation moved into logs, parameter changes, ownership, father/child framing, and finally returning to Rhy.

The state updater is updating events, but active plot is not being resolved cleanly.

You need:

```txt
active_plot_add
active_plot_resolve
dominant_current_plot
```

Current plot should be one compact line, not a growing semicolon list.

### 5. Memory hygiene is becoming a problem

By mid-run, relevant memories included many low-value or repetitive memories:

```txt
Aurora felt a faint flush...
Aurora observed Rhy's direct greeting...
Aurora admitted she did not know...
Aurora answered the door...
Met Junhwa...
```

Some are useful, but many are too granular or repetitive. The brief is still compact enough right now, but it is trending toward clutter.

Memory should prefer:

```txt
durable relationship facts
major self-concept changes
active unresolved tensions
important world facts
```

and deprioritize:

```txt
generic body reactions
repeated "she felt X"
routine observations
one-off phrasing
```

### 6. Time is better, but still not clean

The visible chat did not massively hallucinate time like before. Good.

But payload snapshots later show `Time elapsed: 0` instead of a clean value like:

```txt
Session start
```

or:

```txt
Elapsed time not established
```

That is a small but real normalization bug. Time should become a typed field, not free text.
