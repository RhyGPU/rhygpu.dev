## 8. 내가 보기엔 게임의 “재미 핵심”은 이거임

그냥 수학 퀴즈 게임처럼 만들면 재미없음. 
핵심은:

> 수학을 “문제 풀이”가 아니라 “전투 자원 조작”으로 느끼게 만드는 것.

예를 들어:

- x를 키우면 주문이 강해진다

- 짝수/홀수 조건 카드가 있다
- 소수일 때만 발동하는 카드가 있다
- 확률 카드로 리스크를 건다
- 함수 카드가 서로 연결된다

즉, 플레이어가 “문제를 맞히는 것”이 아니라 
**수학적 구조를 이용해서 빌드를 만드는 게임**이어야 함.

> **Slay the Spire 스타일의 수학 판타지 카드 배틀**, 첫 프로토타입은 `x` 변수 조작과 공식 기반 데미지를 중심으로 만든다.

# 1. 핵심 게임 루프 정리

현재 컨셉을 게임 루프로 정리하면 이거임.

## 기본 전투 루프

1. 적에게 락온한다.
2. 적의 방정식을 확인한다.
3. 다크소울식 전투로 회피, 방어, 패링, 공격을 한다.

# 2. 제일 중요한 규칙 수정: 연산은 “양변에 적용”해야 함

네 예시를 수학적으로 안정되게 만들려면 이렇게 정의하는 게 좋음.

적의 공식:

```text
x + 5 = 10
```

플레이어가 **뺄셈의 검**으로 `5`를 입력하고 적중시키면:

```text
x + 5 - 5 = 10 - 5
```

결과:

```text
x = 5
```

즉, 사칙연산 무기는 적의 방정식 한쪽에만 작동하는 게 아니라 **양변에 같은 연산을 적용하는 무기**로 정의해야 함.

그러면 교육적으로도 맞고, 플레이어가 실제 방정식 풀이를 몸으로 하는 느낌이 남.

## 연산 무기 규칙

| 무기 | 입력 | 효과 |
|---|---:|---|
| 덧셈 무기 | `+n` | 양변에 `n`을 더함 |
| 뺄셈 무기 | `-n` | 양변에서 `n`을 뺌 |
| 곱셈 무기 | `×n` | 양변에 `n`을 곱함 |
| 나눗셈 무기 | `÷n` | 양변을 `n`으로 나눔 |
| X의 검 | `x = n` | 정답 판정 공격 |

예시:

```text
2x = 10
```

나눗셈의 검으로 `2`를 입력:

```text
2x ÷ 2 = 10 ÷ 2
```

결과:

```text
x = 5
```

이렇게 해야 시스템이 깔끔해짐.

# 3. 전투 시스템 이름 정리

용어를 이렇게 잡으면 Codex에도 넣기 좋음.

## Enemy Equation

적의 실제 체력 역할.

예시:

```text
x + 5 = 10
```

## Equation State

현재 전투 중 변형된 식.

처음:

```text
x + 5 = 10
```

뺄셈 5 적중 후:

```text
x = 5
```

## True Answer

실제 정답.

```text
x = 5
```

## Main Stagger

세키로 체간 비슷한 메인 그로기.

- 일반 공격으로 상승
- 치명타로 크게 상승
- 가득 차면 적이 긴 시간 무력화
- 이때 식 풀이, 숫자 입력, X의 검 사용이 쉬워짐

## Parry Stagger

패링 성공 시 짧은 무력화.

- 아주 짧음
- 바로 치명타 가능
- 치명타는 메인 그로기를 크게 채움
- 직접 처형보다는 그로기 빌드업용

# 4. 추가 그로기 후보

네가 `iii+`라고 한 부분은 아래가 좋음.

## iii) Guard Break Stagger

적이 방어 중일 때 특정 무기나 강공격으로 방어를 깨면 발생.

특징:

- 패링 그로기보다 길고 메인 그로기보다 짧음
- 곱셈 무기, 대형 무기, 둔기가 잘 발생시킴
- 방어형 적 상대로 중요함

## iv) Equation Break Stagger

수식을 크게 단순화했을 때 발생.

예시:

```text
3x + 12 = 27
```

플레이어가 `-12`를 성공시켜:

```text
3x = 15
```

이렇게 식 단계가 줄어들면 적이 잠깐 흔들림.

특징:

- 수학적 플레이 보상
- 단순 공격만 하는 플레이와 차별화
- “정확한 연산을 맞히면 전투가 유리해진다”는 느낌을 줌

## v) Overload Stagger

곱셈/나눗셈/버프 등으로 식이 급격하게 바뀔 때 발생.

예시:

```text
x = 33
```

버프 `×3`을 걸어 `x = 99` 처형 가능 상태가 됨.

특징:

- 고위험 고보상
- 곱셈 계열과 버프 빌드의 핵심
- 실패하면 플레이어도 반동 피해 또는 스태미나 손실

내 추천은 프로토타입에는 **Main Stagger, Parry Stagger, Equation Break Stagger**까지만 넣는 것.

# 5. 숫자 입력 시스템은 이렇게 가는 게 좋음

네 아이디어인 숫자 휠은 맞음. 
다만 “구르기나 방어로 한 글자 삭제”는 전투 조작과 충돌할 가능성이 큼.

프로토타입에서는 이렇게 하는 게 좋음.

## Number Wheel Mode

락온 중 특정 키를 누르면 숫자 휠이 열림.

예시 조작:

| 입력 | 기능 |
|---|---|
| `Q` | 숫자 휠 열기 |
| 마우스 휠 또는 숫자키 | 숫자 선택 |
| 좌클릭 | 현재 숫자 추가 |
| 우클릭 | 한 글자 삭제 |
| `Space` | 입력 확정 |
| `Shift/Roll` | 입력 취소하고 회피 |

전투 중에도 가능하지만, 매우 위험해야 함.

## 답 입력 위험도

- 그냥 전투 중 입력하면 느리고 위험함
- 메인 그로기 중 입력하면 안전함
- 패링 그로기 중 입력하면 시간이 짧아서 숙련자만 가능함
- 암산으로 바로 맞히면 Instant Kill

이러면 암산 실력이 자연스럽게 실력 요소가 됨.

# 확정된 핵심 철학

이 게임은 **수학 실력을 제한하지 않는다.**

플레이어가 암산을 잘해서 처음 보자마자 답을 알면, 그냥 바로 X의 검으로 처형 가능해야 함. 
그걸 막으면 교육 게임으로서 오히려 핵심 보상이 사라짐.

따라서 X의 검 규칙은 이렇게 확정.

```text
정답 입력 + X의 검 적중 = 즉시 처형
오답 입력 + X의 검 적중 = 적 진화
```

그로기는 “정답 처형 조건”이 아니라 **안전하게 입력하고 맞힐 수 있는 전투적 기회**임.

즉:

- 수학 잘하면 즉시 처형
- 액션 잘하면 그로기 만들어서 안전하게 처형
- 둘 다 잘하면 사기
- 사기여도 됨
- 대신 오답이면 적이 진화함
- 큰 숫자를 쓰면 내구도가 많이 닳음

이게 맞음.

# 1. X의 검 수정안

이전에는 X의 검을 “느리고 위험한 특수무기”처럼 말했는데, 이건 고정하면 안 됨.

수정:

## X 계열 무기

X의 검도 일반 무기군처럼 다양해야 함.

| 무기 | 성향 |
|---|---|
| X Dagger | 빠른 정답 찌르기, 내구도 낮음, 리치 짧음 |
| X Rapier | 빠른 단일 처형용, 패링 후 찌르기 좋음 |
| X Straight Sword | 기본형, 균형 잡힘 |
| X Greatsword | 느리지만 튼튼함, 큰 숫자 입력에 적합 |
| X Greathammer | 매우 느림, 내구도 높음, 그로기 중 안정적 |
| X Staff / Wand | 마법사 빌드용, 원거리 정답 입력 가능할 수도 있음 |

## X의 검 공통 규칙

```text
입력한 숫자가 정답이면 즉시 처형
입력한 숫자가 틀리면 적 진화
숫자값만큼 내구도 소모
```

예시:

```text
적: x = 99
플레이어가 X의 검에 99 입력 후 적중
결과: 즉시 처형, X의 검 내구도 99 소모
```

이렇게 하면 큰 숫자를 아는 것도 강하지만, 장비 관리가 필요해짐.

# 2. 암산 보너스는 밸런스 제한이 아니라 연출 보상

이것도 수정.

암산 보너스는 시스템적으로 “추가 조건”이 아니라, **뽕맛 연출**이어야 함.

예시 이름:

```text
Axiom Execution
Answer Break
True Solution
해답 처형
공리 처형
진리의 일격
```

발동 조건 예시:

```text
전투 시작 후 짧은 시간 안에 정답 처형 성공
메인 그로기 없이 정답 처형 성공
식 변형 없이 정답 처형 성공
```

효과:

- 슬로우 모션
- 적의 식이 붕괴하는 연출
- 방정식이 `x = answer`로 찢어짐
- 검에 숫자가 새겨짐
- 보상 증가
- 전투 로그에 특수 메시지 출력

하지만 처형 자체는 그냥 정답이면 항상 가능.

# 3. 종족별 공식 특성 확정

여기 아주 중요함. 
랭크가 올라간다고 아무 공식이나 붙으면 종족 정체성이 무너짐.

그래서 구조를 이렇게 나눠야 함.

```text
Species Formula Identity
Enemy Rank Scaling
Mathematical Armor
```

즉, 몬스터 종족은 기본 공식 타입을 결정하고, 랭크는 숫자 크기나 계수만 키우고, 추가 항이나 괄호 같은 복잡성은 Mathematical Armor가 담당함.

# 4. Base Formula와 Mathematical Armor 분리

이게 핵심 데이터 구조임.

## Base Formula

종족 고유의 생명 공식.

예시, 오크:

```text
5x = 10
```

고랭크 오크:

```text
25x = 125
```

이건 OK. 
여전히 곱셈 몬스터임.

하지만 이렇게 바뀌면 안 됨:

```text
5x + 10 = 35
```

이건 오크의 기본 공식에 덧셈이 추가된 거라서, 종족 정체성을 흐림.

대신 이건 **Mathematical Armor**로 처리해야 함.

## Mathematical Armor

기본 공식 위에 덧씌워진 갑옷, 방패, 저주, 버프, 장비 효과.

예시:

```text
Base Formula:
5x = 25

Armor:
+10

Displayed Equation:
5x + 10 = 35
```

플레이어가 `-10`으로 갑옷을 벗기면:

```text
5x = 25
```

그 후 `÷5` 또는 X의 검 `5`로 처형 가능.

이 구조가 좋음.

---

# 5. 몬스터 종족별 공식 체계

## Slime

역할:

- 유저가 강해진 걸 느끼게 하는 적
- 답을 거의 알려주는 적
- 하지만 가끔 레벨 제한으로 창의적 해결을 요구함

공식:

```text
x = n
```

예시:

```text
x = 3
x = 8
x = 99
```

슬라임은 수학적으로 쉬움. 
문제는 **내가 그 숫자를 사용할 수 있느냐**임.

예:

```text
Slime: x = 99
Player level: 11
```

플레이어는 99를 직접 못 씀.

해결 방법:

```text
X Sword input: 11
Mage support buff: ×9
Final execution value: 99
```

단, 마법사 NPC가 `×9` 버프를 주려면 그 마법사의 레벨이 최소 9 이상이어야 함.

이거 좋음. 슬라임이 쉬운데도 상황에 따라 퍼즐이 됨.

---

## Goblin

역할:

- 덧셈/뺄셈 기본 방정식 담당
- 초반 주력 몬스터

공식:

```text
x + a = b
```

또는:

```text
x - a = b
```

랭크 상승:

```text
x + 5 = 10
x + 23 = 28
x + 64 = 91
```

종족 정체성은 “덧셈/뺄셈” 유지.

---

## Frog / Frok

역할:

- 덧셈 계열이지만 정답이 prime number인 특수 몬스터
- 플레이어에게 소수 개념을 자연스럽게 익히게 함

공식:

```text
x + a = b
```

조건:

```text
x는 항상 prime number
```

예시:

```text
x + 4 = 11
x = 7
```

```text
x + 10 = 23
x = 13
```

특성:

- 독 속성 가능
- 습지 몬스터
- 불속성에 약함
- 불속성 무기로 때리면 메인 그로기 증가량 상승

---

## Orc

역할:

- 곱셈 방정식 담당
- 크고 느리고 강함

공식:

```text
ax = b
```

랭크 상승:

```text
5x = 10
25x = 125
40x = 320
```

추가항 금지. 
`5x + 10 = 35`는 오크 기본 공식이 아니라 갑옷이 붙은 오크로 처리.

예시:

```text
Base:
5x = 25

Armor:
+10

Displayed:
5x + 10 = 35
```

---

## Beastman / Centaur / 반인반수

역할:

- 나눗셈, 비율, 분수 담당

공식:

```text
x / a = b
```

또는:

```text
x = a/b
```

예시:

```text
x / 3 = 5
x = 15
```

```text
x / 4 = 2
x = 8
```

후반에는 분수 정답도 가능:

```text
x / 3 = 1/2
x = 3/2
```

초반에는 자연수 결과만 쓰고, 분수 해금 이후에 진짜 분수 몬스터로 확장하면 좋음.

---

## Skeleton

역할:

- 음수 담당

공식:

```text
x + a = b
```

단, 정답이 음수.

예시:

```text
x + 8 = 3
x = -5
```

음수 해금 전에는 처형 불가하거나, NPC/아이템으로 우회해야 함.

---

## Armored Knight 몬스터, 인간 아님

네 피드백대로 인간 적은 필요 없음. 
그러면 “기사”는 인간이 아니라 다음처럼 가면 됨.

- Living Armor
- Hollow Armor
- Animated Knight
- Golem Knight
- Equation Armor

역할:

- Mathematical Armor 튜토리얼
- 기본 공식은 단순하지만 갑옷 때문에 복잡해 보임

예시:

```text
Base:
x + 5 = 10

Armor:
×2

Displayed:
(x + 5) × 2 = 20
```

갑옷을 깨면:

```text
x + 5 = 10
```

# 6. 랭크 시스템 수정

이제 랭크는 “공식 종류 추가”가 아니라 **종족 공식 내 숫자 스케일링**임.

## 잘된 랭크 상승

오크:

```text
Rank 1: 5x = 10
Rank 2: 25x = 125
Rank 3: 60x = 420
```

고블린:

```text
Rank 1: x + 5 = 10
Rank 2: x + 23 = 28
Rank 3: x + 71 = 106
```

프록:

```text
Rank 1: x + 4 = 11, x = 7
Rank 2: x + 18 = 31, x = 13
Rank 3: x + 44 = 73, x = 29
```

## 잘못된 랭크 상승

오크:

```text
Rank 1: 5x = 10
Rank 2: 5x + 10 = 35
```

이건 랭크 상승이 아니라 Mathematical Armor 추가임.

# 7. 숫자 내구도 시스템 확정

이거 매우 좋음.

## 기본 규칙

```text
숫자 휠로 입력한 모든 액션은 입력 숫자값만큼 내구도를 소모한다.
```

예시:

```text
-5 공격: 무기 내구도 5 소모
×9 버프 공격: 무기 또는 촉매 내구도 9 소모
X=99 처형: X 무기 내구도 99 소모
```

이렇게 하면 큰 숫자를 쓰는 게 강하지만 장비 부담이 생김.

## 0의 내구도 문제

0은 특수 처리 필요함.

추천:

```text
0 입력은 내구도 1 소모
```

이유:

- 0을 완전 무료로 두면 악용 가능
- 하지만 수학적으로 0의 특수성을 살릴 수 있음
- 0은 “값은 없지만 행위 비용은 있다”로 처리하면 됨

# 8. 무기군과 내구도 밸런스

## 곱셈 무기

곱셈은 큰 숫자와 잘 어울리므로 내구도가 높아야 함.

예시:

| 무기 | 특성 |
|---|---|
| Multiplication Greatsword | 느림, 내구도 높음, 큰 숫자 입력에 적합 |
| Multiplication Greathammer | 매우 느림, 내구도 매우 높음, 그로기 파괴 강함 |
| Multiplication Axe | 화력 높음, 반동 가능 |
| Multiplication Dagger | 빠르고 강하지만 자해/저주/내구도 소모 심함 |

곱셈 단검 기믹 좋음.

예시:

```text
Multiplication Dagger
- 매우 빠름
- ×n 적용 가능
- 내구도 낮음
- n이 클수록 플레이어에게 반동 피해
- 암살자 빌드용
```

---

## 나눗셈 무기

방어와 생존 중심.

```text
Division Shield
- 방어력 높음
- 패링 판정 넓음
- 공격력 낮음
- ÷n 적용
```

```text
Division Parrying Dagger
- 패링 쉬움
- 패링 그로기 짧음
- 치명타 피해 낮음
- 보조무기용
```

---

## 뺄셈 무기

빠른 식 제거용.

```text
Subtraction Rapier
- 빠름
- 후딜 짧음
- 낮은 그로기 피해
- 갑옷 제거에 좋음
```

---

## 덧셈 무기

기본형.

```text
Addition Longsword
- 균형형
- 초보자용
- 안정적인 내구도와 공속
```

# 9. 속성, 상태이상, 판타지 요소

이것도 반드시 넣을 수 있음. 
단, 수학 시스템과 충돌하지 않게 “전투 보조 효과”로 넣는 게 좋음.

## 속성

| 속성 | 효과 예시 |
|---|---|
| Fire | 특정 종족의 메인 그로기 증가량 상승 |
| Ice | 적 이동속도 감소 |
| Poison | 지속적으로 그로기 축적 또는 행동속도 저하 |
| Lightning | 패링 성공 시 추가 그로기 |
| Holy | 언데드/음수 계열에 강함 |
| Dark | 큰 숫자 입력 시 추가 피해, 대신 자해 |
| Blood | 흡혈 |
| Arcane | Mathematical Armor에 추가 피해 |

예:

```text
Frok is weak to Fire.
Fire weapon attacks build Main Stagger faster against Frok enemies.
```

---

## 흡혈

흡혈은 HP가 없는 적에게도 가능함. 
적의 “식 안정성”이나 그로기 게이지를 흡수한다는 설정으로 처리하면 됨.

예시:

```text
Blood X Rapier
- 정답 처형 성공 시 플레이어 체력 회복
- 오답 시 플레이어도 피해
```

---

## 독

독은 적 HP를 깎는 게 아니라 이렇게 가면 좋음.

```text
Poison builds enemy Main Stagger over time.
```

또는:

```text
Poison slows enemy movement and attack recovery.
```

이러면 HP 없는 시스템과 잘 맞음.

```text
NPC가 사용하는 숫자 또는 배율은 NPC 레벨 이하만 가능하다.
```

```text
Enemy slime: x = 99
```

가능.

불가능.

# 13. Codex 프롬프트에 반영할 핵심 수정 문장

나중에 최종 프롬프트 만들 때 아래 문장들을 넣으면 됨.

```text
The game must not punish mathematical skill by artificially preventing instant correct answers. If the player knows the answer and lands a valid X weapon hit with the correct input, the enemy must be defeated immediately, regardless of stagger state.
```

```text
Stagger is not a requirement for execution. Stagger only creates a safer combat window for number input and X weapon attacks.
```

```text
Enemy rank should scale the numbers inside the monster's species-specific formula pattern. It should not add new mathematical terms to the base formula. Extra terms, parentheses, multipliers, or wrappers should come from a separate Mathematical Armor system.
```

```text
Every number-wheel action consumes weapon durability equal to the numeric value entered. For input 0, consume 1 durability as a minimum action cost.
```

```text
There should be no human enemy faction. Enemy types should be monsters, beasts, slimes, constructs, undead, cursed armor, or abstract mathematical entities.
```

```text
Support NPCs also have levels. A support NPC cannot apply a numeric buff or multiplier greater than their own level.
```

프로젝트 루트에 `AGENTS.md` 파일을 만들고 아래를 넣어.

```md
# Project: Math Souls Prototype

## Project Identity

This is a third-person educational fantasy soulslike prototype built in Unreal Engine.

Core concept:
The player survives soulslike combat while fighting enemies whose "health" is represented by mathematical equations. The player uses weapons based on arithmetic operations, plus, minus, multiply, divide, and X weapons, to transform equations or directly execute enemies by entering the correct value of x.

This is not a quiz game with combat decoration. The math must be part of the combat system itself.

## Core Design Philosophy

1. Mathematical skill must be rewarded, not restricted.
 If the player knows the correct answer and lands a valid X weapon hit with the correct input, the enemy must be defeated immediately, regardless of stagger state.

2. Stagger is not required for execution.
 Stagger only creates a safer combat window for number input, equation manipulation, or X weapon attacks.

3. Wrong answers are punished through enemy evolution.
 If the player lands an X weapon hit with an incorrect answer, the enemy rank increases and the equation regenerates into a harder version.

4. Enemies do not use normal HP.
 Enemies are defeated by solving or correctly answering their equation.

5. Normal attacks and critical attacks mainly build Main Stagger.
 They do not reduce HP because enemies do not have conventional HP.

6. Every number-wheel action consumes weapon durability equal to the numeric value entered.
 If the input is 0, consume 1 durability as the minimum action cost.

7. Species formula identity must be preserved.
 Enemy rank scales numbers inside the monster species' base formula pattern. Rank must not add unrelated terms to the base formula.

8. Extra mathematical complexity belongs to Mathematical Armor.
 Additional terms, parentheses, multipliers, wrappers, or shields must be represented as separate armor or modifiers, not as changes to the species' base formula.

9. There should be no human enemy faction.
 Enemies should be monsters, beasts, slimes, constructs, undead, cursed armor, spirits, demons, or abstract mathematical entities.

10. Keep violence stylized and non-graphic.
 Use cartoon fantasy visuals, impact effects, equation shatter effects, and magical execution animations. Do not implement gore.

## Engine Direction

Use Unreal Engine C++ as the primary implementation layer.
Blueprints may be used only for simple wiring, UI binding, animation hookup, and tuning values.

The prototype should use placeholder meshes, capsules, simple VFX, and toon/cel-shaded materials.

## Coding Standards

- Use clean modular C++ classes.
- Prefer data-driven systems using UDataAsset where appropriate.
- Keep equation logic separate from combat logic.
- Keep weapon data separate from player controller logic.
- Avoid full symbolic algebra parsing in the first prototype.
- Use a simple structured equation model.
- Prioritize a working playable prototype over visual polish.

## Prototype Scope

Build a single 1v1 arena duel.

Required systems:
- Third-person movement
- Lock-on targeting
- Stamina
- Dodge roll with i-frames
- Block
- Parry
- Light attack
- Heavy attack
- Weapon switching
- Main Stagger
- Parry Stagger
- Equation Break Stagger
- Number input system
- Operation weapon hits
- X weapon execution
- Wrong-answer enemy evolution
- Durability loss based on numeric input
- Basic enemy AI
- Combat UI
- Cartoon-style placeholder visuals

Do not implement:
- Multiplayer
- Co-op
- Large-scale army battles
- Full inventory grid
- Save system
- Full story mode
- Real quest system
- Complex animation assets
- Full symbolic equation parser

## Naming Tone

The tone is fantasy, mathematical, and slightly anime-like.

Good terms:
- X Weapon
- Axiom Execution
- True Solution
- Equation Break
- Mathematical Armor
- Main Stagger
- Parry Stagger
- Number Wheel
- Formula Beast
- Algebraic Weapon
```

```text
For the first prototype:

MultiplyArmor

Displayed:
(x + 5) * 2 = 20

If player uses Division weapon with input 2 and hits:
Armor is removed.
Equation becomes:
x + 5 = 10

This should trigger a short Equation Break Stagger.

------------------------------------------------------------
OPERATION WEAPON RULES
------------------------------------------------------------

Arithmetic weapons apply operations to both sides of the current equation or to the active Mathematical Armor layer.

Addition weapon:
- Input n
- Applies +n to both sides or interacts with armor if relevant.

Subtraction weapon:
- Input n
- Applies -n to both sides or removes +n armor.

Multiplication weapon:
- Input n
- Applies *n to both sides.
- High power weapons may cause player recoil depending on weapon data.

Division weapon:
- Input n
- Applies /n to both sides.
- Cannot divide by zero.
- Can remove MultiplyArmor when input matches armor multiplier.

X weapon:
- Input n
- If n equals TrueAnswer, enemy dies immediately.
- If n is wrong, enemy evolves.

Important:
X weapon execution does not require stagger.
If the player knows the answer and lands the hit, kill the enemy.

------------------------------------------------------------
ENEMY EVOLUTION
------------------------------------------------------------

If player hits with an X weapon using the wrong answer:
- Enemy does not die.
- Enemy rank increases by 1.
- Enemy regenerates a harder equation using the same species formula type.
- Enemy keeps its species identity.
- Enemy becomes briefly empowered.
- Enemy exits stagger.
- Show a combat log message.

Example:
Goblin Rank 1:
x + 5 = 10, answer 5

Wrong X hit.

Goblin Rank 2:
x + 23 = 28, answer 5

For prototype simplicity, keep the same true answer when possible, but increase the surrounding numbers.

Orc example:
Orc Rank 1:
5x = 25, answer 5

Wrong X hit.

Orc Rank 2:
25x = 125, answer 5

Slime example:
Slime Rank 1:
x = 7

Wrong X hit.

Slime Rank 2:
x = 17

It is okay for Slime's answer to change because DirectValue monsters are meant to be simple but can catch players off guard through level/number restrictions later.

------------------------------------------------------------
STAGGER SYSTEM
------------------------------------------------------------

- Enemy has a MainStaggerGauge.
- Normal attacks increase it.
- Heavy attacks increase it more.
- Critical attacks increase it greatly.
- Elemental weaknesses increase Main Stagger buildup.
- When full, enemy enters Main Stagger for several seconds.
- During Main Stagger, enemy cannot attack.
- After Main Stagger ends, gauge resets.

Parry Stagger:
- Triggered by successful player parry.
- Very short.
- Allows critical attack.
- Critical attack greatly increases Main Stagger.

Equation Break Stagger:
- Triggered when player removes Mathematical Armor or significantly simplifies the equation.
- Short stagger.
- Rewards correct math manipulation.
```

# 4. 내 추천 결론

**UE로 가는 게 맞음.** 
카툰 그래픽이면 더더욱 좋아. 리얼리즘 소울라이크가 아니라, **애니 판타지 + 수식 파괴 연출 + 과장된 무기 실루엣**으로 가면 컨셉이 훨씬 잘 살아남.

Unity로 갈 이유는 “내가 C#이 훨씬 편하고, 빠른 프로토타입만 원한다”일 때임. Unity도 Cinemachine과 Input System 조합으로 카메라/입력 구현은 가능하고, ScriptableObject로 데이터 관리도 편함. ([Unity Documentation](https://docs.unity3d.com/Packages/com.unity.cinemachine%403.1/manual/InputSystemComponents.html))

```text
This is not a math quiz with combat. This is a soulslike combat game where equations are enemy life, arithmetic is weapon interaction, and correct answers are executions.
```

# Unreal을 깔면 생길 가능성 높은 문제

- 에디터 실행 자체가 느림
- 프로젝트 열 때 오래 걸림
- 셰이더 컴파일 지옥
- 팬 소음/발열 심함
- 배터리 녹음
- 카툰 셰이더, 포스트프로세싱, 라이트 넣으면 버벅임

# 1. “초등수준부터” 전략, 맞지만 조건이 있음

## 잘못 가는 경우
- 문제를 “읽고 → 생각하고 → 계산” 
→ 학교 느낌, 이탈

## 맞는 방향
- **전투 중 자연스럽게 연산이 발생**

예:
- 슬라임 → x=7 → 바로 X로 찌름 → 쾌감
- 고블린 → x+5=10 → 무의식적으로 “-5 때림”

👉 “문제 풀이” 느낌이 나면 실패 
👉 “행동이 곧 풀이”면 성공

## 1.3 핵심 경험 (Core Experience)

```text
싸운다 → 시간을 번다 → 수식을 이해한다 → 변형한다 → 정답을 찌른다 → 처형한다
```

플레이어는 “문제를 푸는 사람”이 아니라:

> **수학을 무기로 사용하는 전사**

---

## 1.4 핵심 철학

1. 수학 실력은 제한되지 않는다 
2. 정답은 언제든 처형 가능하다 
3. 전투는 풀이 시간을 벌기 위한 수단이다 
4. 오답은 실패가 아니라 상황 악화다 
5. 수학은 UI가 아니라 시스템이다

# 4. 수학 시스템 (Core System)

## 4.1 적의 생명 구조

적은 HP가 없다.

```text
적 = 방정식
```

예:

```text
x + 5 = 10
```

---

## 4.2 목표

```text
x = 정답
```

---

## 4.3 연산 무기 규칙

모든 연산은 **양변에 적용**

| 무기 | 효과 |
|---|---|
| 덧셈 | 양변 +n |
| 뺄셈 | 양변 -n |
| 곱셈 | 양변 ×n |
| 나눗셈 | 양변 ÷n |

---

## 4.4 X의 검 (Execution System)

```text
정답 입력 + 적중 = 즉시 처형
오답 입력 + 적중 = 적 진화
```

- 그로기 필요 없음
- 위험도 존재
- 핵심 킬 메커닉

---

# 5. 숫자 시스템

## 5.1 숫자 입력

- 0~9 입력
- 자리수 확장 가능
- UI: 초기 키 입력 → 후속 숫자 휠

---

## 5.2 내구도 시스템

```text
입력 숫자 = 내구도 소모
```

예:

- 5 입력 → 내구도 5 감소
- 99 입력 → 내구도 99 감소

---

## 5.3 0 처리

```text
0 입력 = 최소 1 내구도 소모
```

# 6. 적 시스템

## 6.1 구조

모든 적은:


## 6.2 Base Formula (종족 정체성)

```text
x = n
```

```text
x + a = b
```

---

### Frok (Prime)
```text
x + a = b, x는 소수
```

---

### Orc
```text
ax = b
```

---

### Beast / Centaur
```text
x / a = b
```

---

### Skeleton
```text
x + a = b, x는 음수
```

## 6.3 Mathematical Armor

수식 외부 장비

예:

```text
(x + 5) × 2 = 20
```

---

### 제거 방식

```text
÷2 → Armor 제거
```

---

## 6.4 적 진화 시스템

오답 시:

- 랭크 증가
- 숫자 증가
- 공격 강화

---

## 6.5 랭크 규칙

✔ 허용:
```text
5x = 10 → 25x = 125
```

❌ 금지:
```text
5x = 10 → 5x + 10 = 35
```

# 1. 아이템 종류, 최종 구조 제안

아이템은 크게 **8종류**로 나누는 게 좋음.

## 1. Operation Weapons, 연산 무기

게임의 핵심 장비.

종류:

- Addition Weapon, 덧셈 무기
- Subtraction Weapon, 뺄셈 무기
- Multiplication Weapon, 곱셈 무기
- Division Weapon, 나눗셈 무기
- X Weapon, 해답 무기

이건 기존 GDD의 12장 무기 시스템을 더 확장하는 영역임. 모든 사칙연산은 모든 무기군에 존재 가능하고, 이상한 조합은 기믹 무기, 저주받은 무기, 전설 장비, 상징적 아이템으로 처리한다는 원칙 유지. 

예시:

| 아이템 | 타입 | 역할 |
|---|---|---|
| Addition Straight Sword | 덧셈 직검 | 기본형, 초보자용 |
| Subtraction Rapier | 뺄셈 레이피어 | 빠른 식 제거 |
| Multiplication Greatsword | 곱셈 대검 | 큰 수, 높은 내구도, 느림 |
| Multiplication Dagger | 곱셈 단검 | 빠르고 위험한 자해 기믹 |
| Division Shield | 나눗셈 방패 | 방어, Armor 제거 |
| X Rapier | X 레이피어 | 빠른 정답 찌르기 |
| X Greatsword | X 대검 | 큰 숫자 처형용 |

**결론:** 이 게임에서 무기는 “데미지 도구”가 아니라 **수학 행동을 수행하는 장치**임.

---

## 2. Defensive Gear, 방어구

방어구는 단순 방어력보다 **전투 생존 + 수학 입력 안정성**에 영향을 줘야 함.

종류:

- Helmet, 투구
- Chest Armor, 흉갑
- Gauntlets, 장갑
- Leg Armor, 각반
- Cloak, 망토
- Mathematical Ward, 수식 보호구
- Formula Mantle, 공식 망토

방어구가 줄 수 있는 효과:

| 효과 | 설명 |
|---|---|
| 물리 방어 | 일반 피격 피해 감소 |
| 스태미나 안정성 | 방어/회피 후 스태미나 회복 보정 |
| 숫자 입력 안정성 | 숫자 입력 중 피격 시 취소 확률 감소 |
| 그로기 저항 | 플레이어가 밀려나는 정도 감소 |
| 속성 저항 | Fire, Poison, Dark 등 대응 |
| 연산 저항 | 특정 수식 저주, 오답 페널티 완화 |

예시 아이템:

- **Proofplate Armor** 
 무거운 갑옷. 숫자 입력 중 피격되어도 쉽게 끊기지 않음.

- **Acolyte’s Number Hood** 
 방어력은 낮지만 현재 적의 공식 타입을 더 빨리 분석함.

- **Null-Ward Cloak** 
 0 관련 저주나 무효화 공격에 강함.

---

## 3. Catalysts, 촉매/보조 장비

스태프, 주문서, 부적, 계산 도구 계열.

이건 무기와 다르게 직접 때리는 장비가 아니라, **숫자와 연산을 증폭하거나 보조하는 아이템**임.

종류:

- Staff, 지팡이
- Wand, 완드
- Talisman, 부적
- Abacus, 주판
- Compass, 수학 나침반
- Chalk, 분필
- Rune Slate, 룬 석판

역할:

| 역할 | 설명 |
|---|---|
| 숫자 증폭 | 입력값에 ×n 보정 |
| 내구도 절감 | 큰 숫자 입력 비용 감소 |
| Armor 분석 | Mathematical Armor 타입 표시 |
| NPC 버프 강화 | 아군 연산 지원 효율 증가 |
| 안전 입력 | 숫자 입력 모드 중 방해 감소 |

예시:

- **Apprentice Abacus** 
 입력 숫자가 10 이하일 때 내구도 소모 1 감소.

- **Prime-Finder Charm** 
 Frok 계열 적의 정답이 소수인지 표시하거나 힌트 제공.

- **Multiplier’s Chalk** 
 다음 X 무기 입력값에 ×2 적용. 사용 후 소모.

## 4. Consumables, 소모품

소모품은 물약만 있으면 재미없음. 이 게임에서는 소모품도 수학 시스템에 붙어야 함.

종류:

- 회복 물약
- 스태미나 물약
- 숫자 버프 아이템
- 연산 버프 아이템
- 내구도 회복 아이템
- 오답 페널티 완화 아이템
- 공식 분석 아이템

예시:

| 아이템 | 효과 |
|---|---|
| Minor Health Flask | 체력 회복 |
| Stamina Draught | 스태미나 회복 |
| Oil of Durability | 현재 무기 내구도 회복 |
| Chalk of +1 | 다음 연산에 +1 보정 |
| Times Powder | 다음 입력값 ×2 |
| Eraser Dust | 현재 입력 숫자 즉시 제거, 입력 실수 복구 |
| Formula Lens | 적의 Base Formula와 Armor 구분 표시 |
| Prime Salt | Frok에게 추가 그로기 |
| Null Drop | 0 관련 퍼즐/전투에서 사용 |

중요한 점: 
**소모품이 정답을 대신 풀어주면 안 됨.** 
대신 “선택지를 넓히고, 리스크를 줄이고, 장비 한계를 넘게 해주는 역할”이 맞음.

## 5. Upgrade Materials, 강화 재료

강화 재료는 이 게임의 무기 내구도, 숫자 허용량, 연산 안정성과 연결해야 함.

종류:

- 금속 재료
- 수학적 결정
- 몬스터 드롭
- Armor 파편
- 숫자 조각
- 개념 파편

예시:

| 재료 | 용도 |
|---|---|
| Slime Numeral Gel | 초급 무기 강화 |
| Goblin Sum Shard | 덧셈/뺄셈 무기 강화 |
| Orc Product Core | 곱셈 무기 내구도 강화 |
| Frok Prime Gland | 소수 관련 장비 제작 |
| Broken Equation Plate | Mathematical Armor 장비 제작 |
| Null Fragment | 0 관련 장비 제작 |
| Negative Bone | 음수 장비 제작 |
| Fraction Horn | 분수 장비 제작 |

강화 방향:

- Max Durability 증가
- Numeric Durability Cost 감소
- 특정 연산 효율 증가
- 특정 종족 상대 보너스
- 반동 피해 감소
- 그로기 축적 증가

## 6. Key Items, 핵심 진행 아이템

스토리와 수학 해금을 담당하는 아이템.

이건 팔거나 버리면 안 되는 계열.

종류:

- 숫자 해금 아이템
- 자리수 해금 아이템
- 수학 개념 해금 아이템
- 스토리 유물
- 보스 처치 증표

예시:

| 아이템 | 해금 |
|---|---|
| The First Mark | 숫자 1 |
| Vessel of Nothing | 숫자 0 |
| Place-Value Seal | 10의 자리 |
| Debt-Ledger Bone | 음수 |
| Divided Chalice | 분수 |
| Rooted Sigil | 루트 |
| Function Loom | 함수 |

이건 GDD 16장의 철학 퍼즐과 직결됨. 숫자는 단순 입력값이 아니라 플레이어가 세계를 이해하는 방식이라고 이미 설정되어 있으므로, Key Item은 **세계관 진행 + 수학 커리큘럼 진행**을 동시에 담당해야 함.

# 3. 구현 기준, UE 데이터 구조

여기서 중요한 건 **아이템을 하드코딩하지 말고 데이터화**하는 것임.

Unreal에서는 아이템 정의를 `UPrimaryDataAsset` 기반으로 두는 게 좋음. Epic 문서 기준으로 Unreal의 Asset Manager는 에셋을 Primary Asset과 Secondary Asset으로 나누고, Primary Asset은 Asset Manager가 직접 다룰 수 있는 에셋임. ([Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/asset-management-in-unreal-engine?utm_source=chatgpt.com)) `UPrimaryDataAsset`은 `GetPrimaryAssetId`와 asset bundle support를 가진 DataAsset이라고 설명되어 있어서, 무기/장비/소모품 정의에 적합함. ([Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UPrimaryDataAsset?utm_source=chatgpt.com))

또한 아이템 분류는 enum만으로 막으면 나중에 확장성이 떨어짐. Unreal Gameplay Tags는 사용자 정의 계층형 라벨로, 프로젝트 객체에 붙이고 평가할 수 있으므로 `Item.Weapon.Operation.Subtraction`, `Element.Fire`, `Enemy.Frok`, `Math.Prime` 같은 구조에 적합함. ([Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/using-gameplay-tags-in-unreal-engine?utm_source=chatgpt.com))

# 4. 아이템 카테고리 설계 원칙

## 원칙 1, 모든 아이템은 수학 또는 전투에 의미가 있어야 함

그냥 “잡템”은 최소화.

나쁜 예:

```text
낡은 컵
평범한 돌
일반 허브
```

좋은 예:

```text
깨진 주판알
고블린의 합계 장부
오크의 곱셈 핵
0이 새겨진 빈 그릇
```

---

## 원칙 2, 아이템은 플레이어의 한계를 우회하게 해줘야 함

예:

플레이어 레벨 11. 
적 `x = 99`.

직접 99 입력 불가.

아이템 선택지:

- `×9` 버프 촉매
- `+88` 보정 주문서
- NPC Mage 지원
- X Greatsword의 특수 옵션
- 일회성 “Times Powder”

이렇게 아이템이 단순 스탯 증가가 아니라 **수학적 우회로**가 되어야 함.

---

## 원칙 3, 큰 숫자는 강하지만 비용이 있어야 함

이미 바이블에 있는 “숫자값만큼 내구도 소모” 규칙 유지.

그래서 아이템은 다음 중 하나를 제공해야 함.

- 큰 숫자를 버티는 내구도
- 내구도 소모 감소
- 반동 완화
- 숫자 입력 보조
- NPC 버프 강화

---

## 원칙 4, 교육 아이템은 정답지를 주면 안 됨

아이템이 “정답 보기”가 되면 게임이 망가짐.

대신:

- 공식 타입 공개
- Armor 구조 공개
- 소수 여부 힌트
- 현재 입력값이 가능한 범위인지 표시
- 약점 연산 추천

정답을 직접 보여주는 아이템은 극히 제한하거나, 튜토리얼/접근성 옵션으로 분리.

```md

피타고라스의 조율에서 아이템은 단순한 보상이나 수치 상승 장치가 아니다. 아이템은 플레이어가 수학적 한계, 전투 위험, 장비 내구도, 적의 수식 구조를 다루는 방식이다.

2. 이 아이템은 어떤 전투 상황을 안전하게 만드는가?
3. 이 아이템은 플레이어의 숫자 한계를 어떻게 우회하게 하는가?
4. 이 아이템은 어떤 적 공식 또는 Mathematical Armor에 대응하는가?

## 아이템 대분류

아이템은 다음 대분류를 가진다.

1. Operation Weapons
2. X Weapons
3. Defensive Gear
4. Catalysts
5. Consumables
6. Upgrade Materials
7. Key Items
8. Quest Items
9. Runes / Modifiers

## 핵심 원칙

모든 아이템은 수학 시스템, 전투 시스템, 성장 시스템 중 최소 하나와 연결되어야 한다.

무의미한 잡템은 최소화한다. 잡템이 존재하더라도 세계관, 제작, 판매, 강화, 튜토리얼 중 하나의 목적을 가져야 한다.

정답을 직접 제공하는 아이템은 기본 시스템에서 사용하지 않는다. 아이템은 정답을 대신 알려주는 것이 아니라, 플레이어가 정답에 도달하거나 정답을 실행할 수 있도록 도와야 한다.
```

```text
Addition Weapon
Subtraction Weapon
Multiplication Weapon
Division Weapon
X Weapon
Y Weapon
Z Weapon
```

여기서 중요한 수정점:

- **Addition/Subtraction/Multiplication/Division** = 식을 변형하는 연산 무기
- **X/Y/Z Weapon** = 변수를 찔러 넣는 해답 무기
- X는 1변수 방정식
- Y/Z는 후반부 2변수, 3변수, 좌표, 벡터, 함수 시스템용

즉, X/Y/Z는 전부 “해답 무기”지만 용도가 갈림.

| 해답 무기 | 용도 |
|---|---|
| X Weapon | 기본 1변수 해답 처형 |
| Y Weapon | 연립방정식, 좌표, 함수 보조 변수 |
| Z Weapon | 3차원, 공간, 벡터, 후반 고급 수학 |

초반에는 **X Weapon만 구현**. 
Y/Z는 GDD에 “후속 확장”으로 박아두는 게 좋음.

# 3. 무기군을 전부 연산과 결합하는 방식

전체 조합 구조:

```text
OperationType × WeaponFamily
```

예:

```text
Addition + Rapier
Subtraction + Rapier
Multiplication + Rapier
Division + Rapier
X + Rapier
Y + Rapier
Z + Rapier
```

즉, 모든 무기군은 모든 연산/변수 타입을 가질 수 있음.

다만 조합별로 자연스러운 정도가 다름.

## 자연 조합

| 조합 | 이유 |
|---|---|
| Subtraction Rapier | 빠르게 항을 제거하는 느낌 |
| Multiplication Greatsword | 큰 수, 큰 내구도, 큰 타격 |
| Division Shield | 방어, 분리, 나누기 |
| X Rapier | 정확한 답 찌르기 |
| Addition Straight Sword | 기본형, 균형 |

## 이상하지만 좋은 기믹 조합

| 조합 | 처리 |
|---|---|
| Multiplication Dagger | 빠르지만 반동/자해/저주 |
| Division Greathammer | “거대한 수를 쪼개는 성물” |
| X Shield | 정답 반사/보스 전용 |
| Addition Great Hammer | 느리지만 안정적으로 수를 보정 |
| Z Dagger | 고급 좌표 암살 무기 |
| Y Bow | 좌표 보정 원거리 지원 |

## 전설/LORE 아이템 조합

| 조합 | 콘셉트 |
|---|---|
| Null Greatsword | 0을 다루는 금기 무기 |
| Infinity Spear | 무한을 찌르는 창 |
| Prime Rapier | 소수만 관통하는 검 |
| Equalizer Shield | 양변 균형을 강제하는 방패 |
| Pythagorean Compass | 기하 보스용 성물 |

# 4. 방어구, 장신구는 넣는 게 맞음?

결론: **장신구 넣어야 함.** 
다만 갑옷과 역할이 달라야 함.

네 방어구 슬롯:

```text
Helmet
Chest Armor
Gauntlets
Leg Armor
Cloak
```

이건 좋음. 여기에 장신구를 추가하되, 방어구처럼 물리 방어를 주는 게 아니라 **수학/마나/입력/내구도/저주/속성 보정**을 담당하게 하면 됨.

## 추천 장신구 슬롯

너무 많으면 인벤토리 피곤해짐. 최종 추천:

```text
Ring Slot 1
Ring Slot 2
Amulet Slot
Charm Slot
```

즉, 장신구 4칸.

## 장신구 종류

| 종류 | 역할 |
|---|---|
| Ring | 특정 연산/숫자 보정 |
| Amulet | 속성/저주/방어 보조 |
| Charm | 소형 특수 효과 |
| Brooch | 망토/진영/아군 보조 |
| Belt | 소모품 슬롯/장비 중량 보정 |
| Earring | 감지/Insight 보정 |
| Seal | 수학 개념 해금/제약 완화 |
| Rosary/Beads | 마나/기도/반복 연산 |
| Talisman | 속성/방어/마법 보정 |

## 예시 장신구

| 아이템 | 효과 |
|---|---|
| Ring of Conservation | 숫자 내구도 소모 일부 감소 |
| Prime Charm | Frok의 소수 정답 힌트 강화 |
| Null Amulet | 0 관련 공격/저주 저항 |
| Equal Sign Brooch | 양변 연산 성공 시 Equation Break 보너스 |
| Variable Earring | X/Y/Z 전환 속도 증가 |
| Abacus Belt | 소모품 또는 숫자 보조 슬롯 증가 |
| Cloak Pin of Clarity | 적 방정식 가독성/분석 속도 증가 |

## 갑옷 내구도

갑옷도 내구도 있는 것 좋음. 대장장이/재료/잡템 필요성이 생김.

갑옷 내구도 규칙 추천:

- 피격 시 갑옷 내구도 감소
- 방어 성공 시 방패/장갑/흉갑 내구도 감소
- 속성 공격은 특정 방어구 내구도를 더 많이 깎음
- 내구도 낮으면 방어력 감소
- 0이 되면 파손 상태, 장착은 가능하지만 효과 크게 감소

수리 재료가 필요한 이유:

| 재료 | 용도 |
|---|---|
| Metal Scrap | 일반 무기/갑옷 수리 |
| Leather Patch | 망토/가죽 방어구 수리 |
| Chain Links | 사슬/경갑 수리 |
| Plate Fragment | 중갑 수리 |
| Equation Dust | 수학 장비 수리 |
| Rune Ink | 룬/촉매 수리 |
| Slime Gel | 초급 접착/보강 |
| Armor Shard | Mathematical Armor 계열 제작 |

잡템도 필요함. 단, 그냥 쓰레기 잡템이 아니라:

```text
수리
제작
판매
퀘스트
강화
연구
```

중 하나로 연결해야 함.

# 5. Catalysts, 촉매/보조 장비 종류

촉매는 “마법을 쓰게 해주는 장비”로 잡자. 
소모품과 다르게, 마법은 **마나를 소모하지만 무한 사용 가능**. 이 방향 좋음.

## 촉매 대분류

| 촉매 종류 | 역할 |
|---|---|
| Staff | 안정적 주문, 긴 캐스팅 |
| Wand | 빠른 주문, 낮은 위력 |
| Rod | 중간형 |
| Scepter | 버프/권위/지휘 |
| Tome | 주문 저장/다양성 |
| Grimoire | 강한 주문, 높은 마나 |
| Scroll Case | 제한된 주문 세트, 빠른 교체 |
| Talisman | 신성/방어/상태이상 |
| Seal | 특정 수학 개념 강화 |
| Orb | 분석/원거리/추적 |
| Crystal | 마나 증폭 |
| Abacus | 숫자 조작/연산 보조 |
| Chalk | 수식 작성/Armor 제거 |
| Compass | 기하/좌표 |
| Ruler | 거리/비율 |
| Protractor | 각도/삼각 |
| Astrolabe | 천문/고급 계산 |
| Lantern | 논리/숨겨진 식 표시 |
| Bell | 공명/광역 그로기 |
| Quill | 식 수정/계약/룬 작성 |
| Ink Bottle | 룬/공식 강화 |
| Slate Tablet | 공식 저장 |
| Dice | Luck/확률 |
| Cards | 확률/조건부 주문 |
| Prayer Beads | 반복 연산/회복 |
| Hourglass | 시간/쿨다운/미적분 DLC |
| Mirror | 반사/대칭/오답 경고 |
| Scale Balance | 양변 균형/방정식 안정화 |

## 촉매별 추천 역할

### Staff

- 마법사 기본 촉매
- 마나 효율 좋음
- 캐스팅 느림
- 큰 주문 가능

예:

```text
Addition Staff
Division Staff
Function Staff
```

### Wand

- 빠른 캐스팅
- 낮은 마나 소모
- 낮은 위력
- 초보 마법/견제

예:

```text
Wand of +1
Wand of Minor Subtraction
```

### Tome / Grimoire

- 주문 슬롯 많음
- 무겁다
- 캐스팅 중 방해받기 쉬움
- 고급 수학 주문에 적합

예:

```text
Tome of Equal Operations
Prime Grimoire
Book of Fractions
```

### Abacus

이 게임 전용 핵심 촉매.

역할:

- 숫자 입력 보정
- 내구도 소모 감소
- NPC 계산 보조
- 큰 숫자 조합

예:

```text
Apprentice Abacus: 10 이하 입력 내구도 소모 감소
War Abacus: 전투 중 입력 속도 증가
Prime Abacus: 소수 관련 힌트 강화
```

### Chalk / Quill / Ink

수식 직접 조작 계열.

역할:

- Mathematical Armor에 강함
- 수식 일부를 표시/강조
- 룬 작성
- 필드 퍼즐 해결

예:

```text
Chalk of Inversion
Rune Ink of Balance
Quill of Correction
```

### Compass / Ruler / Protractor

기하학 DLC 또는 Y/Z 확장에 좋음.

역할:

- 좌표
- 각도
- 거리
- 삼각형/원
- 벡터

예:

```text
Pythagorean Compass
Golden Ruler
Angle-Seeker Protractor
```

### Orb / Crystal / Lantern

분석/마나/탐지형.

역할:

- 적 공식 분석
- 숨겨진 Armor 표시
- 마나 증폭
- 속성 변환

예:

```text
Orb of Clarity
Null Crystal
Logic Lantern
```

### Bell / Hourglass / Mirror

고급/상징 촉매.

역할:

- Bell: 광역 그로기, 공명
- Hourglass: 시간, 쿨다운, 변화율
- Mirror: 대칭, 반사, 오답 경고

예:

```text
Bell of Equal Resonance
Derivative Hourglass
Mirror of Symmetry
```

# 6. 마법은 공격 가능하게 할까?

결론: **가능하게 해야 함.** 
하지만 적에게 HP가 없으니까, 마법 공격은 “HP 데미지”가 아니라 아래 역할을 해야 함.

## 플레이어 마법 공격의 역할

| 마법 역할 | 설명 |
|---|---|
| Stagger Damage | 메인 그로기 축적 |
| Armor Damage | Mathematical Armor 약화 |
| Equation Operation | 원거리 연산 적용 |
| Status Effect | 둔화, 독, 약점 노출 |
| Input Support | 숫자 입력 보호 |
| Buff | X/Y/Z 무기 입력값 증폭 |
| Debuff | 적 공격성/이동속도 감소 |
| Analysis | 공식 타입, Armor 타입 표시 |

즉:

```text
마법은 죽이는 수단이 아니라, 식을 다루고 전투 상황을 바꾸는 수단.
```

단, 예외적으로 **X/Y/Z 마법**은 처형 가능하게 할 수 있음. 
하지만 이건 위험함. 원거리 정답 처형이 너무 편해지기 때문.

## 추천 규칙

### 일반 공격 마법

가능.

예:

- Fire Bolt: Frok의 메인 그로기 빠르게 증가
- Poison Cloud: 적 이동 둔화 + 그로기 지속 축적
- Arcane Pulse: Mathematical Armor에 추가 피해
- Ice Rune: 적 공격 회복 지연
- Lightning Mark: 패링 성공 시 추가 그로기

### 연산 마법

가능.

예:

- `Minor Subtract`: 원거리로 양변에 `-1`
- `Divide Seal`: Armor `×2` 약화
- `Balance Spell`: 잘못 적용한 연산 일부 되돌림
- `Equalize`: 양변 적용 성공률 증가

### 해답 마법

조심해서 가능.

추천 제약:

- 캐스팅 길다
- 마나 많이 든다
- 방해받으면 취소
- 오답이면 적 진화 + 마나 과부하
- Catalyst 요구
- 보스는 일부 저항 가능

예:

```text
X Ray Spell
입력값이 정답이면 원거리 처형 가능.
하지만 캐스팅 시간이 길고, 오답 시 적이 즉시 진화한다.
```

이건 후반 고급 마법으로 두는 게 좋음.

# 7. 적도 마법 공격 가능하게 할까?

결론: **무조건 가능하게 해야 함.**

이유:

- 적 다양성 증가
- 수학 시스템을 방어적으로도 쓰게 됨
- 마법사형 적, 보스, Abstract Entity 설계 가능
- 장신구/방어구/촉매의 존재 이유가 생김

## 적 마법 공격 종류

| 적 마법 | 효과 |
|---|---|
| Numeric Curse | 플레이어 입력값 제한 |
| Input Scramble | 현재 입력 숫자 흐림/방해 |
| Durability Drain | 장비 내구도 손상 |
| Mana Burn | 마나 감소 |
| Equation Fog | 적 방정식 일부 가림 |
| False Term | 가짜 항 표시, 고급 적용 |
| Armor Regrowth | Mathematical Armor 재생 |
| Rank Surge | 일정 시간 랭크 강화 |
| Zero Seal | 0 입력 제한 |
| Prime Lock | 소수가 아닌 입력 약화 |
| Fraction Bind | 이동 둔화, 분수 DLC용 |
| Variable Swap | X/Y/Z 혼동, 후반용 |

이건 진짜 게임성을 살릴 수 있음.

단, 초반에는 너무 과하면 안 됨. 
초반 적 마법은 단순해야 함.

## 초반 적 마법 추천

| 적 | 마법 |
|---|---|
| Frok | Poison Spit, 이동 둔화/그로기 압박 |
| Goblin Shaman | Equation Fog, 수식 일부 흐림 |
| Living Armor | Armor Regrowth, Armor 재생 |
| Skeleton Mage | Negative Curse, 음수 개념 전까지 약한 저주 |

# 9. 내 판정

정리하면:

1. **무기군은 매우 넓게 열어도 됨.** 
 다만 현실 무기 백과사전이 아니라 `WeaponFamily` 중심의 게임 분류로 가야 함.

2. **장신구는 넣는 게 맞음.** 
 갑옷은 생존/내구도/무게, 장신구는 수학/마나/입력/저주/속성 보정.

3. **갑옷 내구도, 포션, 재료, 잡템 필요함.** 
 대장장이/수리/강화/제작 루프 때문에 필수.

4. **촉매는 대량으로 가능.** 
 특히 주판, 분필, 컴퍼스, 자, 천구의, 저울은 이 게임만의 상징 아이템으로 강함.

5. **마법 공격은 가능하게 해야 함.** 
 하지만 적 HP를 깎는 공격이 아니라, 그로기/Armor/수식/상태이상/버프 중심이어야 함.

6. **적도 마법 공격 가능하게 해야 함.** 
 그래야 장비, 장신구, 촉매, 저항, 입력 방해 시스템이 의미를 가짐.
