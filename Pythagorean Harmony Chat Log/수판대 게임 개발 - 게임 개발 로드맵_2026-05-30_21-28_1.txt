# AGENTS.md

## Project

Pythagorean Harmony is a prototype for a fantasy third-person action RPG where enemies are defeated by solving equations through combat.

## Current Goal

Build only the first playable prototype:

Math Souls Prototype: Equation Duel

The current target is a 1v1 combat prototype where:

- The enemy displays an equation
- The player inputs a number
- The player hits the enemy with an X weapon
- Correct answer causes instant execution
- Wrong answer causes enemy evolution

## Engine

Unreal Engine 5  
Third Person C++ Template

## Development Rules

Keep the project prototype-focused.

Do not implement:

- Multiplayer
- Full inventory
- Save system
- Open world
- Full symbolic algebra parser
- Boss fights
- Large-scale battles
- DLC systems
- Final art pipeline

## Code Style

Use Unreal Engine C++ conventions.

Prefer:

- Actor Components for reusable systems
- Data-driven structs and enums
- Blueprint-exposed functions where useful for testing
- Simple logic first
- Clear comments for beginner readability

Avoid:

- Overengineering
- Complex symbolic parsing
- Large inheritance chains
- Unnecessary plugins
- Marketplace dependencies

Priority order:

1. Equation system
2. Number input system
3. Enemy equation display
4. X answer check
5. Wrong answer evolution
6. Operation weapon logic
7. Basic combat connection

**Intended Architecture**

The first prototype should be a small UE5 third-person combat loop built around components, not a big RPG framework.

The player remains mostly the Third Person C++ Template character. We add number input and simple weapon/action calls. The enemy is a single prototype enemy actor, initially Goblin, with an equation component that owns the current equation, answer, rank, and evolution state. UI/Blueprints can read from C++ to display the equation, current input, and combat log.

The core flow should be:

1. Goblin owns equation: x + 5 = 10, answer 5
2. Player enters a number through a number input component
3. Player hits Goblin with an X weapon
4. Combat resolver asks enemy equation component whether input is correct
5. Correct answer executes enemy
6. Wrong answer increments enemy rank and swaps/hardens equation state
7. Operation weapons later transform the equation in a simple, explicit way
